# Requerimientos Funcionales
## General
| **ID**    | **Equipo**               | **Requerimiento**                  | **Descripción Detallada**                                                                                                                                                                                                      |
| --------- | ------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| RF_GEN001 | Frontend                 | Menú de Navegación (Visitante)     | Para cualquier usuario no autenticado (Visitante), el menú de navegación principal debe mostrar, como mínimo, los enlaces a:<br>- Inicio<br>- Configurador<br>- Iniciar Sesión<br>- Registrarse                                |
| RF_GEN002 | Frontend                 | Menú de Navegación (Cliente)       | Si un usuario "Cliente" está autenticado, el menú principal debe cambiar para **ocultar** "Iniciar Sesión" y "Registrarse", y **mostrar**:<br>- Inicio<br>- Configurador<br>- Mis Pedidos<br>- Contacto<br>- **Cerrar Sesión** |
| RF_GEN003 | Frontend                 | Menú de Navegación (Vendedor)      | Si un usuario "Vendedor" está autenticado, el menú principal debe cambiar para mostrar enlaces al Panel de Administración (ej. "Gestionar Pedidos") y **"Cerrar Sesión"**.                                                     |
| RF_GEN004 | Backend<br>x<br>Frontend | Funcionalidad "Cerrar Sesión"      | Al hacer clic en el enlace/botón "Cerrar Sesión" (disponible para Cliente y Vendedor), el sistema debe:<br>1. Destruir la sesión activa del usuario.<br>2. Redirigir al usuario a la página de Bienvenida (Index).             |
| RF_GEN005 | Backend<br>x<br>Frontend | Control de Acceso Global (Admin)   | El sistema debe verificar el rol del usuario en **cada** petición a una URL administrativa (ej. `/admin/*`). Si el usuario no es "Vendedor", debe ser redirigido a la página de Bienvenida (o la de Cliente).                  |
| RF_GEN006 | Backend<br>x<br>Frontend | Control de Acceso Global (Cliente) | El sistema debe verificar que el usuario esté autenticado en **cada** petición a una URL de cliente (ej. `/mis-pedidos/`). Si no está autenticado, debe ser redirigido a "Iniciar Sesión".                                     |
| RF_GEN007 | Backend                  | Persistencia de Sesión             | Una vez que un usuario inicia sesión, su estado de autenticación (sesión) debe mantenerse activo y ser reconocido en todas las páginas del sitio hasta que presione "Cerrar Sesión".                                           |
| RF_GEN008 | Frontend                 | Consistencia del Pie de Página     | El sistema debe mostrar el mismo pie de página (footer) en todas las páginas visibles para el Visitante y el Cliente.                                                                                                          |

## Página de Configurador
| **ID**      | **Equipo**               | **Requerimiento**                        | **Descripción Detallada**                                                                                                                                                                                                                                                                                                        |
| ----------- | ------------------------ | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RF_CPC001   | Frontend                 | Visualización Pública                    | El sistema debe mostrar la página del "Configurador" a cualquier usuario (Visitante o Cliente) sin requerir autenticación.                                                                                                                                                                                                       |
| RF_CPC002   | Frontend                 | Interfaz (Formulario Único)              | El sistema debe mostrar un **único formulario** donde el Cliente define **todos** sus requisitos:<br>1. Necesidades (ej. "Gaming-AAA")<br>2. Almacenamiento (ej. "1TB")<br>3. Tamaño de Gabinete (ej. "Mid-Tower")<br>4. Conectividad (ej. "Wi-Fi Requerido")                                                                    |
| RF_CPC002.1 | Frontend                 | Modificador de Necesidades               | Para las distintas necesidades, el sistema debe mostrar un modificador que permita aumentar los requerimientos                                                                                                                                                                                                                   |
| RF_CPC003   | Frontend                 | Acción de Búsqueda                       | El sistema debe tener un botón (ej. "Encuentra mi PC Ideal") que envíe el formulario completo al backend.                                                                                                                                                                                                                        |
| RF_CPC004   | Backend                  | Lógica DANIEL (Traducción)               | Al recibir el formulario, el sistema debe traducir **todas** las entradas del cliente a requisitos técnicos (Gamas):<br>- "Gaming-AAA" -> `Gama_CPU >= 8`, `Gama_GPU >= 8`<br>- "1TB" -> `Gama_Almacenamiento >= 5`<br>- "Mid-Tower" -> `Gama_Gabinete = 3`                                                                      |
| RF_CPC005   | Backend                  | Lógica DANIEL (Búsqueda Kit)             | El sistema debe buscar en la tabla **`Kits_Funcionales`** el kit que cumpla los requisitos de `Gama_CPU` / `Gama_GPU`.                                                                                                                                                                                                           |
| RF_CPC006   | Backend                  | Lógica DANIEL (Búsqueda Kit Estructural) | El sistema debe buscar en la tabla **`Kits_Estructurales`** el kit que cumpla el requisito de `Gama_Gabinete`.                                                                                                                                                                                                                   |
| RF_CPC007   | Backend                  | Lógica DANIEL (Cálculo Precio Total)     | `Precio Total = Precio_Kit_Funcional` (de RF_CPC006) + `Precio_Kit_Estructural` (de RF_CPC007) + `Precio_Almacenamiento`.                                                                                                                                                                                                        |
| RF_CPC008   | Backend                  | Lógica DANIEL (Filtro Presupuesto)       | El sistema debe verificar si el `Precio_Total` (RF_CPC008) es menor o igual al `Presupuesto_Máximo` del cliente (si este lo definió).                                                                                                                                                                                            |
| RF_CPC009   | Backend<br>x<br>Frontend | Muestra de Resultado Único               | Si la búsqueda es exitosa (Kit encontrado + Componentes encontrados + Dentro del presupuesto), el sistema debe presentar al cliente la **PC combinada** como un resultado único, mostrando:<br>- Nombre (ej. "Tu Configuración Ideal")<br>- Lista de todos los componentes (Kit + Personalización)<br>- El `Precio_Total` final. |
| RF_CPC010   | Frontend                 | Manejo de Cero Resultados                | Si la búsqueda falla (ningún Kit cumple, o se pasa de presupuesto), el sistema debe mostrar un mensaje amigable (ej. "No encontramos una PC con esos criterios.").                                                                                                                                                               |
| RF_CPC011   | Frontend                 | Acción de Pedido                         | El resultado (RF_CPC010) debe tener un botón "Realizar Pedido".                                                                                                                                                                                                                                                                  |
| RF_CPC012   | Backend<br>x<br>Frontend | Flujo de Pedido (Visitante)              | Si un Visitante (no logueado) hace clic en "Realizar Pedido", el sistema debe:<br>1. Almacenar la **combinación completa** (ID del Kit + IDs de componentes) y el `Precio_Total` en la sesión.<br>2. Redirigirlo a la página de "Iniciar Sesión".                                                                                |
| RF_CPC013   | Backend<br>x<br>Frontend | Flujo de Pedido (Cliente)                | Si un Cliente (logueado) hace clic en "Realizar Pedido", el sistema debe:<br>1. Crear un nuevo `Pedido` con el `Precio_Total`.<br>2. Asociar a ese Pedido el ID del `Kit_Base` y los IDs de los componentes de personalización (Almacenamiento, Gabinete, etc.).<br>3. Redirigir al Cliente a su página de "Mis Pedidos".        |

| RF_REG009 | Backend<br>x<br>Frontend | Manejo de Errores                | Si alguna validación (RF_REG003 a 006) falla, el sistema debe mostrar un mensaje de error específico (ej. | RF_REG010 | Backend<br>x<br>Frontend | Enlace a Login                   | El sistema debe mostrar un enlace o botón claro para que los usuarios que ya tienen una cuenta puedan navegar a la página de "Iniciar Sesión".                                                                                                 |
